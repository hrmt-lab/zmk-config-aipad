# ブリングアップとトラブルシュート

新しい基板に火を入れるとき、あるいは動かなくなったときの手順です。



## 無表示は「正常」の可能性がある

Rendererは`session_active = false`を`SCREENKEY_RENDERER_OFF`として扱い、
ロゴを隠して**バックライトを消灯**します。

Keylink StudioがAI Client Stateを送っていない状態では、**配線が完璧でも4画面とも真っ暗**です。
正常な画面と壊れた画面が見分けられません。これがセルフテストが存在する理由です。

## 手順1: バックライトbeaconでファームが動いているか見る

`CONFIG_AIPAD_DISPLAY_SELFTEST=y`のとき、起動直後にバックライトを
**1秒ごとに6回点滅させてから点灯したまま**にします（計12秒）。

`SYS_INIT`から実行しPWM LEDしか触らないため、displayドライバ・LVGL・USB・Hostの
いずれにも依存しません。これが重要なのは、ZMKのdisplay moduleは
`chosen zephyr,display`が`device_is_ready()`でない場合に**早期returnし、
`zmk_display_status_screen()`を呼ばない**からです。その場合は画面のセルフテストも
そのログも一切出ませんが、beaconだけは動きます。

| beacon | 示すもの |
|---|---|
| 点滅する | ファームは動作し、PWMバックライト回路も正常。次はパネルとSPI |
| 点滅しない | ファームが起動していないか、バックライト回路／P0.15の問題 |

LED電流がハードで低めに設定されているため100%でもパネルは暗く、目視が怪しいことがあります。
ログに`beacon 1/6`のように回数が出るので、シリアル出力と突き合わせて判断してください。

## 手順2: セルフテストで4画面を切り分ける

`CONFIG_AIPAD_DISPLAY_SELFTEST=y`にすると、Hostと無関係に起動直後へ描画します。
画面indexの偶奇でロゴと枠色を変えるので、隣り合うパネルが必ず別の見た目になります。

| 画面 | ロゴ | 枠 |
|---|---|---|
| 0（CS-1） | Codex | 青 `#3B82F6` |
| 1（CS-2） | Claude Code | 緑 `#22C55E` |
| 2（CS-3） | Codex | 青 |
| 3（CS-4） | Claude Code | 緑 |

これでScreenKeyの物理的な並び順とCS-1〜CS-4の対応を確認できます。
並びが違う場合は`&spi2`の`cs-gpios`の並びを入れ替えれば合わせられます。

| 見え方 | 示すもの |
|---|---|
| 4枚とも出る | パネル・SPI・バックライトは正常。原因はHost側 |
| 特定の1枚だけ出ない | そのCS配線 |
| 全部出ない | 電源／SPI（SCLK P1.03・MOSI P1.12）／DC P1.05／RST P0.02／バックライト P0.15 |
| バックライトも点滅しない | ファームが起動していない |

## 手順3: ログを読む

`CONFIG_ZMK_USB_LOGGING=y`により、USB CDC ACMのシリアルポートへログが出ます。

起動時のログはUSB列挙前なので失われますが、**USB列挙後に10秒間隔で3回、
起動レポートを出し直します**。

```
--- ScreenKey boot report 1/3 (replayed for the USB log) ---
ScreenKey backlight: ready
ScreenKey lcd0: ready
ScreenKey lcd1: ready
ScreenKey lcd2: ready
ScreenKey lcd3: ready
ScreenKey short check: no shorts between judgeable pins
```

| ログ | 意味 |
|---|---|
| `lcd0〜3: ready` | ドライバ初期化は成功 |
| `NOT READY` / `Couldn't init LCD` | LVGLより手前のドライバ初期化で失敗 |
| `ScreenKey screen N unavailable` | N枚目のLVGL登録だけが失敗。残りは動く |
| `Failed to find display device`（ZMK） | `zmk_display_status_screen()`自体が呼ばれていない |
| 何も出ない | USB CDCが列挙されていない |

USB自体が列挙されない場合は、`CONFIG_ZMK_USB_LOGGING=y`を外して
（CDC ACMが2本になるのを避けて）再確認してください。

### 「初期化は通るのに何も映らない」ときはSCLK/CS-3を疑う

パネルはwrite-onlyで読み返しが無いため、SPIクロックが1本も届いていなくても
`st7735r_init()`は成功を返します。`lcd0〜3: ready`と出るのに真っ暗、という状態は
**SCLKとCS-3の取り違え**で起きます。`P1.03`がSCLK、`P1.07`がCS-3です。

判定は次のベースライン測定でできます。

## ピンウォークとショートチェック

セルフテスト有効時、`SYS_INIT`（POST_KERNEL 45）でパネル8信号を1本ずつHighへ駆動します。

各ラインは1秒ずつ保持されログに名前が出るので、0.5mmピッチに触らずに
同じネットの測りやすい点へメーターを当てられます。

### ベースライン測定

駆動前に、全ピンを内部プルダウン付き入力にして一度読みます。
**外部プルアップを持つ線だけがHighのまま**残るので、それが判別できます。

CS 4本には10Kプルアップ（R1 / R3 / R9 / R11）があり、nRF52840の約13Kの内部プルダウンに
対して約1.9Vになります。これは`V_IL`（0.99V）と`V_IH`（2.31V）の間の不定領域なので、
**このピンは短絡判定の対象から除外**されます。

```
ScreenKey short check: CS1 (P1.13/D8, J1 pin 8) has an external pull-up and was not judged
```

除外リストに出るべきなのは**CS 4本ちょうど**です。SCLKが混ざっていたり、
CSのどれかが欠けていたりしたら、ピン割り当てが間違っています。

### 短絡判定

エッジ直後に読むと隣接FPCトレースの容量結合を短絡と誤検出するため、
1ms待ってから、さらに1ms空けて2回読み、両方Highのときだけ短絡と判定します。

## キーが反応しないとき

- **列や行がまるごと死んでいる**: NFCピンのGPIO化を確認する。COL2（P0.10）と
  エンコーダA（P0.09）はNFCパッドです。生成devicetreeの`uicr`ノードに
  `nfct-pins-as-gpios;`があること、`compile_commands.json`で`system_nrf52840.c`が
  `NRF_CONFIG_NFCT_PINS_AS_GPIOS`付きでコンパイルされていることを確認してください。
- **1キーも反応しない**: ダイオードの向きを疑う。逆なら`diode-direction = "row2col"`に
  してcol/rowのGPIOフラグも入れ替えます。
- **`RC(2,3)`が反応しない**: 正常です。プッシュ無しエンコーダのため`&none`です。

## エンコーダが反応しないとき

`CONFIG_AIPAD_ENCODER_PROBE=y`（`CONFIG_GPIO_HOGS=n`と併用）でビルドすると、
エンコーダが繋がり得るピンを監視して5秒ごとに状態を出します。

```
encoder probe: ec11 ready | now P0.09=1 P0.04=1 P0.05=0 P0.31=0
encoder probe: edges P0.09=0 P0.04=0 P0.05=0 P0.31=0 | up/down P0.09=1/1 P0.04=1/1 P0.05=1/0 P0.31=1/0
```

マトリクス・パネル・バックライトが動いているなら、エンコーダはこの4本のどれかにしかありません。

### `up/down` の読み方

内部プルアップで1回、内部プルダウンで1回読んだ結果です。基板側の10Kプルアップは
内部プルダウンに勝つので、配線が届いていれば`1/1`になります。

| up/down | 判定 |
|---|---|
| `1/1` | 外部プルアップあり = 線が基板まで届いている |
| `1/0` | フローティング = 先に何も繋がっていない |
| `0/0` | Lowに固定 = 接点が閉じているかGNDショート |

### `edges` の読み方

ノブを一定方向に10クリックほど回してから見ます。

| 結果 | 判定 |
|---|---|
| 2本が同じくらい増える | 配線は正常。`steps` / `triggers-per-rotation`を調整 |
| `1/1`なのにエッジが増えない | 配線は届いているが接点が閉じていない、または**内部プルアップで分圧されている**（[hardware.md](hardware.md)参照） |
| どちらかが`1/0` | その線が断線 |
| `ec11 NOT READY` | ドライバの初期化失敗 |

### 感触の調整

| 症状 | 対処 |
|---|---|
| 1クリックで2回入力される | `triggers-per-rotation`を半分に |
| 2クリックで1回しか入らない | `triggers-per-rotation`を倍に |
| 方向が逆 | `a-gpios`と`b-gpios`を入れ替える |

## LEDセルフテストで4個のWS2812B-V6を切り分ける

`CONFIG_AIPAD_STATUS_LED_SELFTEST=y`（`CONFIG_AIPAD_STATUS_LED=y`必須）にすると、
起動直後からHostと無関係に、チェーンの先頭（1個目）から**赤→緑→青**の順に1個ずつ点灯しながら
流れていきます。1ステップ200ms、赤・緑・青 × 4個 = 12ステップで、最後にもう1ステップ分
全消灯して通常動作へ引き継ぎます。

一度に光るのは常に1個だけなので、4個それぞれの配線・チェーン順・色順を1回の観察で
まとめて確認できます。

| 症状 | 診断 |
|---|---|
| 何も光らない | P0.05の配線／チェーンの電源／`&spi3`が`okay`になっているかを疑う |
| 1個目だけ光って残りが光らない | 1個目のDIN-DOUT断線、またはその1個目自体の故障 |
| 流れる向きが逆（4個目から流れる） | チェーンの実配線が想定と逆順 |
| 赤と緑が入れ替わって見える | `color-mapping`がGRBになっていない（配線ではなくdevicetree側の問題） |
| 色が混ざる／ちらつく | SPIのビットタイミングを疑う。[hardware.md](hardware.md)のビットタイミングの節を参照し、`spi-max-frequency`を`6400000`（実際は4MHzへ切り下げ）や`spi-one-frame`/`spi-zero-frame`を`0xF8`/`0x80`のような別値へ落として症状が変わるか試す |

## LEDが光らない・おかしいときの切り分け

`device_is_ready(strip)`は`aipad_leds`のドライバが初期化に成功したかどうかしか見ておらず、
**P0.05から先の配線が生きているかは一切確認しません**。ログに`aipad status LED: strip device
not ready`が出ないからといって配線が正しいとは言えず、逆に配線が正しくても
（Hostが状態を送っていない、`CONFIG_AIPAD_STATUS_LED=n`など）LEDが消灯したままのことがあります。

- **ドライバ初期化の失敗を疑う**: `CONFIG_ZMK_USB_LOGGING=y`を足してログに
  `aipad status LED: strip device not ready`が出ないか確認する
- **点灯すべきときに光らない**: まず`CONFIG_AIPAD_STATUS_LED=y`になっているか確認し、
  次にLEDセルフテスト（上記）で配線そのものを確認する。配線が生きているのにHost側の状態で
  光らない場合はKeylink Studio側（承認待ち／入力待ち／エラー／完了のいずれかを送っているか）を疑う
- **配線の生死は目視でしか分からない**: `device_is_ready()`が通っていても`led_strip_update_rgb()`の
  戻り値が失敗ならログに`aipad status LED: strip update failed: %d`が一度だけ出る
  （毎tickのログ洪水を避けるため1回のみ）。それも出ないのに光らないなら、SPI自体は成功していて
  チェーンの物理配線を疑うべきタイミングなので、セルフテストへ進む

### 初回通電の注意

P0.05はこの基板でWS2812Bの逆実装（[hardware.md](hardware.md)の「WS2812Bの向き」参照）により
電源レールを短絡させたことがある経路です。LED追加後の初回通電は、USBの電流計を挟んで
異常電流（発熱前に検出できる）が無いことを確認してから行うのが安全です。

## 発熱しているとき

**発熱は過電流です。** 発熱源で原因が分かれます。

| 熱い場所 | 意味 |
|---|---|
| 3.3Vレギュレータ／充電IC | VCC_3V3の過負荷またはショート |
| nRF52840本体 | GPIOのESDクランプダイオードに電流。GND不通、または未通電の回路へ信号を突っ込んでいる |

無通電の測定が全部通るのに通電すると発熱する、という場合は**極性部品の向き**を疑ってください。
テスターの試験電圧は寄生ダイオードの順方向電圧に届かないため、無通電では正常に見えます。
詳細は[hardware.md](hardware.md)の「WS2812Bの向き」を参照してください。

ブートローダーモード（リセット素早く2回）はアプリのGPIOを一切駆動しないので、
**ハードの問題かファームの問題かを分ける**のに使えます。
ブートローダーでも発熱するならファームは無関係です。
